# Convenciones del equipo

## Ramas (GitHub Flow)
- `main` siempre desplegable, protegida (requiere PR + 1 aprobación)
- Ramas de trabajo: `feature/nombre-corto`, `fix/nombre-corto`, `docs/nombre-corto`
- Se borran al hacer merge

## Commits (Conventional Commits)
feat: nueva función
fix: corrección de bug
docs: solo documentación
chore: config, dependencias, sin cambio de lógica
refactor: cambio de código sin alterar comportamiento

Ejemplo: feat(api): agrega CRUD de tiendas

## Pull Requests
- Título claro, descripción breve de qué y por qué
- Como mínimo 1 aprobación antes de merge a main
- Ligar el PR a la tarea del Sprint Backlog (ID: T1-T17)
